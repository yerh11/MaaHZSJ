# 《魂坠深境》自动脚本 · 使用文档

**这份是写给"跑脚本的人"的**：怎么起、它自己会做什么、什么时候会停、停了怎么办、
想改规则改哪个文件。至于"脚本内部怎么搭的"（认屏表、四层结构、管线协议），
看工作区根目录的 `CLAUDE.md`，这份不重复。

---

## 一、它现在能干到什么程度

一句话：**从主界面开一局 → 走地图 → 处理沿途每个地点、事件、战斗 → 走到结局
（通关或失败）→ 收尾回主界面 → 再开下一局**，这一整圈不用人点。

边界说清楚：

- **游戏内登录还是手动的**。脚本从"已登录"接手 —— 冷启动能看到标题界面或主界面，
  就算登录好了。
- **没定过策略的分支会主动停车**并说清停在哪（见第五节）。**停车不是故障**，
  是"这儿还没教过脚本"。停车永远停在那儿，不会自己乱撞。
- 通关和失败**都**能自己收尾回主界面；胜负会写进日志（判据是结算屏左上角那行标题）。

## 三、怎么跑

```bash
cd MaaHZSJ
export PYTHONIOENCODING=utf-8        # Windows 下必须，否则中文日志会炸
python script/battle.py 噩梦9层
```

- **难度**（缺省 `噩梦9层`）：`普通` / `困难` / `险恶` / `严酷` / `极难` /
  `噩梦1层` ~ `噩梦9层`
- **启动时游戏停在哪都行**（不用先摆好）：
  - 停在**局内**（战斗/地图/某个地点）→ **接着这一局走完**。不重启、不另开一局、
    也不动这一局开局时定的难度；
  - 停在**局外**（主界面/标题界面/公告页）→ 回主界面，开新局。
    ⚠️ **标题界面**那一条有一个例外：**底下其实可能压着一局没打完**（游戏冷启动会
    "接着那一局继续"，2026-10-02 实测）。脚本点进去之后**认得出是哪一屏就接着走**，
    认出来是主界面才开新局 —— 也就是说它不会把一局没打完的进度丢掉。
    ⚠️ 另外，标题界面**有时要连点几下才走**：游戏还没登录时，头一下会被"登录"吃掉
    —— `logcat` 里能看到 TapTap 登录成功，可屏原地不动，得等它一会儿再点一下
    （2026-10-14 实测：`08:06:35` 一下 → `08:06:45` 再一下 → `08:07:06` 到主界面）；
    登录好了的那次（当晚 `20:46:42`）**一下就进**，底下登录与加载画了 27 秒。
    所以日志里连着两三行「停在标题界面」是**正常**的，不是卡住；
    等满 180s 还不动才会停下等人。
- **一局正常收尾会自动开下一局**，一直跑。**停只有两种**：手动 `Ctrl-C`，
  或者"这一局没正常收尾"（停车等人 / 未知界面 / 达到步数上限 / 战斗超时之后
  **连"退出这一局"都走不通**）—— 后者必须有人来看，所以脚本会停住，
  不接着开新局把现场盖掉。
- **一把战斗打超过 5 分钟**不属于上面那种"出事"：脚本会**退出这一局**（放弃），
  收尾回主界面，然后接着开下一局。被放弃的这局**不记胜负**（它不是打通的，
  也不是打输的）。
- 想挂后台跑（推荐，日志落盘）：

  ```bash
  python -u script/battle.py 噩梦9层 > debug/run_$(date +%m%d_%H%M).log 2>&1 &
  ```

- **只想跑一局**，或者接着当前这一局跑（不回主界面、不开新局、不重启）：

  ```bash
  python debug/play.py          # 接着跑
  python debug/play.py 40       # 最多跑 40 步（默认 400）
  ```

## 四、脚本自己会做哪些决定（已经定过的）

这些**不用问人**，脚本直接做完。要改哪一条见第七节。

|---|---|
| 开局 | 主界面 →「启动祭坛」→ 难度轮盘选档 →「坠入深境」 |
| 地图选路 | **按优先表自动选**（表在 `script/nav/map.py` 的 `NODE_PRIORITY`，数字小的先去；同一档取先读到的那个） |
| 地图·只有一条路 | 不管优先表，**直接走**（保底一） |

| 地图·走一步没走成 | **重读地图、重新按优先级挑一条再走**，最多 3 次（保底三，2026-10-03 加）。治的是"读到的位置是歪的"（现场那次读数比真位置低了 64px，命令它去点时它按位置找不到那个节点，一个点击都没发就停车）。三次都走不成才停车 |
| 篝火 | 魂晶够 3 就先「激活护符」（进护符选择界面）；点不动就「坐下休息」（满血不试）；再不行「离开地点」。**三种都不算异常** |
| 护符选择界面 | 按框上**印的号** 1→2→3→4→5 依次点，谁弹出详情面板就激活谁（花 3 魂晶） |
| 已激活护符屏（「选择1个已激活护符，…」，事件「狭缝」选“坠入”之后有时先落这一屏） | **两段式**：① **点最上面那一行**（用户 2026-10-04：「选择第一个护符」；两版卷面「…使其施放冷却-1（最低为1。）」/「…复制其当前状态。」都是这一条）—— 行位置固定、量出来的（第一行名字框 `(110,371,88,24)`，行距 95）；② 这一行点亮后会浮出一张详情卡 + 一枚 **「确认选择」**（量到浮在 `(637,398,81,22)`，score 1.0000），**再点它这一屏才走**（跟这游戏别处的选项一个规矩：光点选项是"高亮"，不算数）。⚠️ 头一版只做了第 ① 步，2026-10-05 实机证伪、当场停车。**接着那一页还没量过**，交给主循环认（认不出就存图停车）。⚠️ 这一屏从前被末尾那行「通用离开屏」按「离开地点」抢走 ⇒ **首领战丢了**，这就是用户报的「不会选择第二个选项，直接面对首领」 |
| 印记石 / 祝福祭坛 | **不碰可选的那一项**（将手放入凹槽 / 触摸祭坛），直接离开 |
| 商店（神秘商人） | 点「移除卡牌」，把非保留卡（`script/cards/保留.json` 里那几张之外的）**一张一张销毁**：点「移除卡牌」→ 弹出**销毁卡牌屏**（标题「你的卡组」）→ 销毁一张 → 面板自己收掉、又站回商店屏 → 再点，直到**没有可销毁的**或**点着了却进不去面板（金币不足）** —— 那时点「离开地点」走人。名单在 `script/cards/保留.json`（事件那条移除屏共用同一份）。**「购买卡牌」不点**（还没定过策略） |
| 销毁卡牌屏（商店点「移除卡牌」之后弹出那屏） | **卡面先筛、名字后验**：四条卡面模板（`assets/resource/pipeline/卡牌族.json`）认出保留名单里的格子 → 不碰；剩下的格子按行优先点开读卡名，名字在名单里 → 以名字为准、换下一格；名字读不出来 → **停车**。挑中之后读屏上那行「支付 N金币」的价钱，金币不够就走人（用户 2026-10-04：「金币不足时或没有可移除时离开」）。销毁一张之后**面板留在原地**（实测），脚本接着清下一张；每次点完「销毁」都**等屏上真少一张**（实测约 0.5s，牌要烧一下），下一轮读网格前也先**等它别再动**（牌在挪位时读到的是过期位置）。两个出口都点左上角返回箭头退回商店屏，由商店点「离开地点」 |
| 选卡屏（标题「选择卡牌」，事件里弹出来的那屏） | **两版移除屏 + 复制屏 + 升级屏，靠副标题分派**：① 副标题「从卡组中选择一张卡牌移除。」→ 扫一遍卡组挑一张不在保留名单里的移除，一张可移除的都没有 → 点左上角「返回」取消；② 副标题「选择最多3张卡牌，将其移除。」（2026-10-04 事件「狭缝」第一次撞上，**这一版没有「返回」**，出口只有底下那枚「确定」）→ 点一张＝**加进选中**、最多 3 张，名单里的牌点开看清名字后当场取消（**点开读名要连点两下**：这一下选中、下一下点回去，净效果为零），选完点「确定」踩实；**一张可移除的都没有也点「确定」走人**（用户 2026-10-04：「可以不选择」）。⚠️ 这一屏**灰罩只在选满 3 张时才出现**，所以"选着 1~2 张"是看不出是哪几张的 —— 进门撞上这种就停车（`cardpick_preselected`），不猜；⚠️ **但"面板亮着"不等于"选着牌"**：那块亮着、还读得出卡名的东西也可能是**别处飘过来的卡牌信息框**（2026-10-09 撞上，上一屏的选中框跟着飘过来了），这时靠**牌框外侧那圈青绿光环**分开 —— **满屏一格光环都没有 ⇒ 一张都没选**，点一下空白把框收掉再照常往下走（收不掉 / 那一记没点出去就停车：`cardpick_infobox_stuck` / `cardpick_infobox_noclick`），有光环才是真选着（照旧停车）；③ **复制屏**（2026-10-06 并成一条路）→ 按默认取左上角第一张，读都不读卡名 —— 用户 2026-10-02 定的是「默认第一张」，2026-10-06 又明确「如果触发了选卡, 默认选第一张」，**两副卷面（副标题读不到的那版 / 写着「选择1张卡牌，复制2张加入牌组。」的那版）动作一模一样**，从前那条"挨格点开读卡名、读到「莽撞头槌」才选它"（`_copy_named` / `COPY_CARD`）整个删了；④ 副标题里带「升级」→ **升级屏**（「选择最多3张可升级卡牌，将其升级。」，2026-10-04 事件「狭缝」→ 第 2 格「“坠入”」之后撞上，是这个入口的第二个落点）→ **一张都不选、一格都不碰，直接点「确定」**（用户 2026-10-04：「一张都不选，直接「确定」」+「照「可以不选」先办」）。⚠️ 2026-10-13 起这里短暂改成过「一律停车等人」（`等待升级现场`，为的是量他教的「卡面周围有金边 ⇒ 已经升级过了」那条判据），**2026-10-14 那次现场真撞上、也量完了 ⇒ 开关已经关回 `False`**（现场帧 `cardpick_upgrade_live.png` 上 2 张牌**都没升级、都没金边**，那只是反例，正例还没有；见第七节）；这一屏的牌是**居中排**的（存档帧上 2 张，列心 868/985、行心 221），与写死的 5 列格子不是一张表，而这一趟本来也不需要格子。前两版（两版移除屏）都**读不出卡名就停车**（分不清是不是名单里的牌）；后两版（复制屏、升级屏）**压根不读卡名** |
| 献祭锻造间 | 进去看一眼：有没升变过的斧头就升（一把 6 金币，能升几把升几把），然后返回、离开 |

## 五、什么时候会停，停了怎么办

停车 = 脚本停下了，理由要么是"这儿没定过策略"，要么是"没读明白"。**每次停车都会
存一张现场图**到 `debug/screenshots/`（图名见下表），那是定策略的唯一凭据。
**同时在 `debug/parks/` 留一份同名的文字记录**（`cardpick_noconfirm.png` ↔
`debug/parks/cardpick_noconfirm.md`）—— 里面写着当时那一刻的**理由 / 现场图名 /
停在哪一屏 / 命中了哪些节点 / 屏上证据 / 第几步 / 分辨率 / 环境 / 最近 30 行日志**。
日志滚出屏幕之后，看那一份就够了；同名的那份会被下一次同名停车覆盖（跟现场图一样）。

| 日志里的理由 | 意思 | 你该做什么 |
|---|---|---|
| `等待事件` / `等待事件（未定策略）` | 撞上没见过的事件，或者事件集里这条 `pick` 还是 `null`；或者 `pick`（连同 `fallback`）那一格**点不动**（现场图 `event_park_<事件名>_noclick.png`；`fallback` 写歪了则是 `_badfallback`） | 看 `events.json` 里那条的选项 + 现场图 `event_new_<事件名>.png`，把该选哪项告诉我 |
| `等待选路` | 地图上读不到可前往节点、那个词条优先表里没定过，或者**连走 3 次都没走成**（每次都重读过、重挑过） | 看现场图 `map_goto_fail.png` / `battle_map.png`，告诉我这个词条排哪儿 |

## 七、想改一条规则

- **事件选哪一项**：改 `script/events.json` 里那条的 `pick`：
  - `0` = 第 1 项，`1` = 第 2 项 ……（**从 0 起算**）
  - `"leave"` = 这一屏什么都不选，走「离开地点」
  - `null` = 策略还没定，**遇到就停车问人**
  - 可选：再加一条 `"fallback"`（同样从 0 起算）= **`pick` 那一格点不动时改选哪一格**。
    用途见「真龙现身」：第 2 格「献上金币」要 15 金币，付不起时游戏根本不理这一下
    （2026-10-05 现场：手里 10 金币、点了两轮都没选中）—— 用户当天定「金币不够就改选
    第 1 格『揭穿他』」⇒ `"fallback": 0`。**退路也是写死的一格**，不是"随便再试一个"；
    两格都点不动就照旧停车。没用这个字段的事件，行为跟从前一样。
  - 可选：再加一条 `"tap"` = 这一屏的选项格**单击还是双击**：不写 = `"double"`
    （缺省，双击），写 `"single"` = 只单击、不点第二下。现在只有「游艺」写 `single`
    （翻牌时第二下会落到下一屏的牌桌上）。写别的值 = **一格都不点、停车**。
    ⚠️ "第二段确认"（浮出「确认选择」/ 同一格再点一下）**不记在这里**，脚本当场认。

  这个文件**每次遇到现读**，改完**不用重启脚本**，下一次撞上就按新的走。
- **哪几张牌保留 / 移除 / 升变 / 升级 / 想拿**：改 `script/cards/` 那五份 —— 都**只写卡名**
  （不带 `+` 后缀；`无畏斧+` 和 `无畏斧` 算同一种牌，脚本自己去掉尾部 `+` 再比）。
  **这五份也是每次用到现读，改完不用重启脚本。**

  | 文件 | 管什么 |
  |---|---|
  | `保留.json` | 要保留、不许动手的卡 |
  | `移除.json` | **优先移除**的卡（压过 `保留.json`） |
  | `升变.json` | 锻造屏上允许升变的卡 |
  | `升级.json` | 升级屏上允许升级的卡（**今天空着**；升级屏现在一律停车，见下面 ⚠️） |
  | `选择.json` | **往卡组里加牌**那两屏上想拿的卡（复制屏 / 加入卡组屏，**今天空着**，见下一条） |

  **`选择.json` 是另一条链**（跟上面那四份互不影响，**也不参与** `均使用` 那套方式）。
  它管的是"**往卡组里加牌**"那两屏：

  | 屏 | 空名单（今天） | 名单非空 |
  |---|---|---|
  | **复制屏**（「选择1张卡牌，复制2张加入牌组。」/ 没副标题那版） | 取左上角第一张 | 挨格读卡名，挑名单里的那张；**屏上一张都没有就还是取第一张**（这一屏写死了"选1张"，不能跳过） |
  | **加入卡组屏**（「可选择最多2张卡牌加入卡组」） | 一张都不拿，直接点「确定」 | 挨格读卡名，挑名单里的、**最多 2 张**；屏上一张都没有就还是**一张都不拿**（这一屏写的是"**可**选择"，能跳过） |

  这一屏最多拿几张是**屏幕自己说的**（复制屏 1 张、加入卡组屏 2 张），名单里命中
  更多也只取读到的前几张。读卡名要逐格点开再点回去（净效果为零），**一张 5 格的屏
  十几秒**，所以只在名单非空时才会去读。名单非空那条路上**每一步读不出来都停车**：
  一格都切不出来（`cardpick_select_nogrid`）/ 卡名读不出来（`cardpick_select_unknown`）/
  选上之后名字对不上（`cardpick_select_mismatch`）。

  **保留 ⇄ 移除是互补的**（一张牌只有"留着"和"动它"两种去向），**这两个名单怎么用
  有四个方式**，今天用的是 `均使用`（= **移除优先**）：一张牌要保留 ⟺ 它在
  `保留.json` 里、**且**不在 `移除.json` 里。所以

  - 想「除了这几张，别的都移除」→ 只往 `保留.json` 里写那几张，`移除.json` 留空；
  - 想「这几张下次也移除」→ 把名字**加进 `移除.json`**，`保留.json` 里那份不用动。

  | 方式 | 一张牌算"保留"的条件 |
  |---|---|
  | `均使用`（今天） | 在 `保留.json` 里、**且**不在 `移除.json` 里（**移除优先**） |
  | `只使用保留` | 在 `保留.json` 里（`移除.json` 整个不参与） |
  | `只使用移除` | 不在 `移除.json` 里（`保留.json` 整个不参与） |
  | `均不使用` | **全都保留** —— 两份名单都不参与，**谁也不动** |

  **换方式改 `script/shared/cards.py` 顶上那一行 `MODE`**（两份配置文件都留着、
  一个字都不用删）。⚠️ 换之前先看那两份里真写了什么：`移除.json` 空着的时候，
  `只使用移除` 会退化成"谁也不动"（因为"不在移除里"恒成立）；`保留.json` 空着的时候，
  `均使用` / `只使用保留` 都退化成"一张都不留"（= 全都能动）。四种方式只有在
  **两份都非空**时才彼此都不同。

  **写坏了脚本会停车，不会猜**：文件缺了 / 不是合法 JSON（这五份是 **JSONC**，
  `//` 与 `/* */` 注释都可以写）/ `卡牌` 那一格不是字符串数组 / 多写了别的键 ——
  一律停车 `等待卡牌配置`（现场图 `cards_config_broken.png`）。

  ⚠️ 三个要知道的：

  - **名字对不上卡面 = 这一屏保护不了它**。名字是权威，但脚本在**只看画面**的那一屏

  - **`升级.json` 一填名字就停车**（`等待卡牌配置` / `cardpick_upgrade_listed.png`）。
    升级屏的牌是**居中排**的，格位与卡面都没量过 —— 不是坏了，是那一路还没定过。
  - **升级屏：`PARK` 那个开关**（`等待升级现场` / `cardpick_upgrade_live.png`）——

    再把它打开、拿那一帧把判据落地（`script/ops/card_upgrade.py` 顶上那段记着量到的数）。
- **地图优先级**：`script/nav/map.py` 的 `NODE_PRIORITY`（数字小的先去）。
- **别的**（某个屏某一步怎么走）：在 `script/nodes/`（地点）/ `nav/`（寻路）/
  `combat/`（战斗）/ `system/`（界面）里找到那一屏的模块，改它的 `handle()`。
  目录怎么分、每层能依赖谁见 `docs/zh_cn/架构与流程图.md`。
  改完请跑一遍第八节那套自检。
- 写 JSON 的注意：**全仓库的 json 都按 JSONC** 处理，`//` 与 `/* */` 注释都可以写
  （脚本运行时那台去注释机器是 `script/shared/jsonc.py`），缩进统一 4 空格。
  ⚠️ 例外只有 `script/events.json` —— 它会被脚本**回写**，注释在那一步会被抹掉，
  所以那一份不写注释，说明用 `_说明` 那几条键。
